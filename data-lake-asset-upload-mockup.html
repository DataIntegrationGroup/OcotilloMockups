Data Lake
Put a tranche of files into Ocotillo storage today  ·  gs://ocotillo-datalake  ·  us-central1 + us-east1, versioned  ·  Editor and above
Lo-fi mockup — not functional. Nothing here is wired: no bucket, no upload, no catalog table, no ingestion job. It proposes a faster on-ramp into Ocotillo storage — somewhere to put a tranche of data now, with normalization following ingestion instead of gating it. Positions this mockup takes, all up for debate:
  • Upload is never blocked on metadata. Four fields are required — dataset, project, sensitivity, ingestion owner — and everything else is added later from the catalog row.
  • The object path is generated, never typed. raw/<project>/<dataset>/<upload-date>/ — no user-authored folder trees, because a folder tree is the network share this is meant to replace.
  • Files may land unlinked to any well, spring, or project record. An orphan tranche in the lake beats a tranche on someone's desktop.
  • Every dataset names an ingestion owner — a person, not a queue. Datasets without one read Unassigned and are counted in the header. That count is the point of the screen.
  • Its own nav item, not a tab under Assets. Assets attach to a record; lake objects have no record yet. Is that the right split, or does it just make two upload buttons?
  • Browser upload caps at 5 GB per file; anything larger gets a generated gcloud storage command. Acceptable, or does this need resumable browser upload on day one?
